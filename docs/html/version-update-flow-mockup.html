Quando a plataforma recebe um deploy

Mockups para decidir como avisar um usuário logado de que saiu uma nova versão, sem interromper o que ele está fazendo, e como transformar o erro seco de "chunk quebrado" numa ação de atualizar. Tema escuro — espelha o app real.

01 O aviso proativo

Duas formas de dizer "há uma atualização". Ambas são dispensáveis; a diferença é onde vivem e como insistem.

Atualização disponível

Uma nova versão da plataforma está pronta. Atualize quando puder.

Não empurra conteúdo. O "Agora não" minimiza — não some (ver seção 2).

Por que recomendo a B: é o padrão consagrado de "nova versão disponível" em web apps. Ela resolve o seu pedido — "pode ignorar, mas sempre lembrar" — de forma limpa: ao ignorar, encolhe para um selo persistente em vez de desaparecer, e não disputa espaço com os banners operacionais do topo (que falam do sistema, não do app).

02 Ignorou? Continua lembrando.

Ao clicar em "Agora não", o card encolhe para este selo no mesmo canto. Ele fica sempre visível, e o card completo reabre sozinho de tempos em tempos (ex.: a cada 15 min) — nunca bloqueia, nunca deixa esquecer.

Orçamentos
Atualização pronta · toque para ver

Clique no selo (ou no card acima na seção 1) para alternar os estados neste mockup.

A régua do lembrete
Aparece: ao detectar deploy Ignorar: minimiza p/ selo Reabre: a cada ~15 min Nunca: bloqueia a tela

O selo persiste entre trocas de rota e sobrevive ao recarregamento do app até que a versão nova seja de fato carregada. Assim que o usuário atualiza, tudo some.

Intervalos e cópia são parâmetros — dá para calibrar o quanto insiste sem tocar na estrutura.

03 Quando o erro chega antes do aviso

Se o usuário clicar numa tela logo após o deploy, o chunk pode dar 404 antes do aviso aparecer. Hoje isso cai numa tela genérica. O plano é reconhecer que é "código desatualizado" e oferecer a mesma ação de atualizar.

Sobre o "hard refresh": o navegador não deixa um site forçar Ctrl+Shift+R por script. Mas o efeito que importa — baixar o build novo — é garantido recarregando o index.html (que a Vercel serve sempre fresco) e limpando o Cache Storage antes. Como cada arquivo já tem hash no nome, isso é suficiente para o app subir 100% na versão nova.
